## 📊 项目概览

### 项目目标

构建一个高性能、易用、生产就绪的上下文压缩系统，支持多种压缩策略，帮助对话系统降低 Token 使用和成本。

### 核心价值

1. **降低成本** 💰
   - 通过智能压缩减少 Token 使用
   - 语义压缩可节省 40-60% Token
   - 缓存优化带来 214x 性能提升

2. **提升性能** ⚡
   - 滑动窗口压缩：~270 ps（皮秒级）
   - LRU 缓存查询：39 ns（纳秒级）
   - Token 计数：7-670 µs（微秒级）

3. **易于集成** 📦
   - 简洁的 API 设计
   - 支持配置文件（TOML/YAML）
   - 完整的文档和示例

## 🎯 核心功能

### 1. 三种压缩策略

#### 滑动窗口（Sliding Window）
**原理**: 保留最近 N 条消息，丢弃旧消息。

**优势**:
- ⚡ 极快（~270 ps）
- 💡 实现简单
- 🔧 易于配置

**适用场景**:
- 短对话（< 50 条消息）
- 实时响应要求高
- Token 预算充足

#### 语义压缩（Semantic）
**原理**: 使用 LLM 将多条消息总结成摘要。

**优势**:
- 💰 节省 Token（40-60%）
- 📝 保留关键信息
- 🎯 信息密度高

**适用场景**:
- 长对话（> 100 条消息）
- 需要保留完整语义
- 归档和总结

#### 分层压缩（Hierarchical）
**原理**: 根据对话特征智能选择策略。

**优势**:
- 🧠 智能决策
- ⚖️ 平衡性能和效果
- 🔄 自适应调整

**适用场景**:
- 通用场景（推荐默认）
- 对话长度不确定
- 需要平衡多种需求

### 2. Token 计数

**功能**:
- 支持多种 LLM 模型（Claude, GPT 等）
- 批量计数优化
- 消息级别统计

**性能**:
- 短文本（10 词）：7 µs
- 长文本（5000 词）：4.6 ms
- 线性时间复杂度 O(n)

### 3. LRU 缓存

**功能**:
- 线程安全（Arc + Mutex）
- 泛型设计（支持任意类型）
- 统计信息（使用率、命中率）

**性能**:
- 查询命中：39 ns
- 插入：80 ns
- 加速比：214x（vs 无缓存）

### 4. 配置管理

**功能**:
- 支持 TOML 和 YAML 格式
- 策略独立配置
- 环境变量覆盖

**灵活性**:
- 代码配置
- 文件配置
- 运行时动态调整

1. **并发性能** ⚠️
   - **问题**: Arc<Mutex> 多线程性能下降 24x
   - **原因**: 锁竞争严重
   - **解决**: 建议使用分片缓存（未来优化）

2. **异步测试** 🧪
   - **问题**: Mock LLM 异步调用测试复杂
   - **解决**: 使用 mockito + tokio-test

3. **配置复杂度** ⚙️
   - **问题**: 三种策略各有配置参数
   - **解决**: 结构化配置 + 合理默认值
