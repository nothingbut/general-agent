# 文件上传功能验收测试指南

**创建时间**: 2026-04-03
**测试范围**: V3 文件上传功能 (Phase 1-5)
**预计耗时**: 30-45 分钟

## 📋 测试环境准备

### 1. 系统要求

- .NET 10.0 SDK
- 至少 1 GB 可用磁盘空间
- 终端/命令行工具

### 2. 构建项目

```bash
cd v3
dotnet build
```

### 3. 准备测试文件

创建以下测试文件：

**test-data/sample.txt**:
```
这是一个简单的文本文件。
包含多行内容。
用于测试文件上传功能。
```

**test-data/config.json**:
```json
{
  "database": {
    "host": "localhost",
    "port": 5432
  },
  "api": {
    "timeout": 30,
    "retries": 3
  }
}
```

**test-data/app.cs**:
```csharp
public class User
{
    public int Id { get; set; }
    public string Name { get; set; }
}
```

## ✅ 测试场景

### 场景 1: 基本文件上传

**目标**: 验证文件可以成功上传

**步骤**:

1. 启动 REPL:
   ```bash
   dotnet run --project src/GeneralAgent.CLI/
   ```

2. 上传文本文件:
   ```
   > /file upload test-data/sample.txt
   ```

**预期结果**:
- ✓ 显示"文件已上传"消息
- ✓ 显示文件 ID、文件名、类型、大小
- ✓ 提示如何引用文件

**验证**:
```
> /file list
```
应该显示刚上传的文件

---

### 场景 2: 上传不同类型文件

**目标**: 验证支持多种文件类型

**步骤**:

1. 上传 JSON 配置文件:
   ```
   > /file upload test-data/config.json
   ```

2. 上传代码文件:
   ```
   > /file upload test-data/app.cs
   ```

3. 列出所有文件:
   ```
   > /file list
   ```

**预期结果**:
- ✓ 所有文件都成功上传
- ✓ 文件类型正确识别（.txt, .json, .cs）
- ✓ 列表显示 3 个文件

---

### 场景 3: 查看文件详情和内容

**目标**: 验证文件信息查看功能

**步骤**:

1. 复制 sample.txt 的文件 ID（例如：abc12345）

2. 查看文件详情:
   ```
   > /file show abc12345
   ```

3. 查看文件内容:
   ```
   > /file content abc12345
   ```

**预期结果**:
- ✓ 详情显示完整的元数据（ID、名称、类型、大小、时间）
- ✓ 统计信息正确（行数、字符数）
- ✓ 内容显示与原文件一致

---

### 场景 4: 在对话中引用文件 ⭐

**目标**: 验证核心功能 - 对话中文件引用

**步骤**:

1. 上传配置文件（如果还未上传）:
   ```
   > /file upload test-data/config.json
   ```

2. 在对话中按文件名引用:
   ```
   > 请分析 @file:config.json 中的配置
   ```

3. 按文件 ID 引用:
   ```
   > 请解释 @file:abc12345 的用途
   ```

**预期结果**:
- ✓ Agent 读取并理解文件内容
- ✓ Agent 回复基于文件内容（例如提到 database、api 等配置）
- ✓ 没有错误提示

**验证要点**:
- Agent 回复中提到文件中的具体内容（如 "localhost"、"5432"、"timeout: 30"）
- Agent 能正确分析配置的用途和含义

---

### 场景 5: 同时引用多个文件 ⭐

**目标**: 验证多文件引用功能

**步骤**:

1. 确保已上传 sample.txt 和 config.json

2. 同时引用两个文件:
   ```
   > 比较 @file:sample.txt 和 @file:config.json 的内容类型
   ```

**预期结果**:
- ✓ Agent 能同时读取两个文件
- ✓ Agent 回复中提到两个文件的内容
- ✓ Agent 能正确对比分析（文本 vs 配置）

---

### 场景 6: 文件上传到记忆

**目标**: 验证记忆集成功能

**步骤**:

1. 创建一个包含重要信息的文件 test-data/project-notes.txt:
   ```
   项目架构决策：
   - 使用微服务架构
   - 数据库选择 PostgreSQL
   - 缓存使用 Redis
   ```

2. 上传并提取到记忆:
   ```
   > /file upload test-data/project-notes.txt --to-memory
   ```

3. 搜索记忆:
   ```
   > /memory search "架构"
   ```

**预期结果**:
- ✓ 文件上传成功
- ✓ 显示"正在提取文件内容到记忆..."
- ✓ 显示保存的记忆数量和类型
- ✓ 搜索记忆时能找到提取的内容

---

### 场景 7: 删除文件

**目标**: 验证文件删除功能

**步骤**:

1. 列出文件:
   ```
   > /file list
   ```

2. 删除其中一个文件（交互式）:
   ```
   > /file delete abc12345
   ```
   确认提示时输入 `y`

3. 验证删除:
   ```
   > /file list
   ```

**预期结果**:
- ✓ 显示确认提示
- ✓ 确认后显示"文件已删除"
- ✓ 文件列表中不再显示该文件

**额外测试** - 强制删除:
```
> /file delete xyz67890 --force
```
应该直接删除，无需确认

---

### 场景 8: 错误处理 - 文件不存在

**目标**: 验证错误处理

**步骤**:

1. 上传不存在的文件:
   ```
   > /file upload /path/to/nonexistent.txt
   ```

2. 引用不存在的文件:
   ```
   > 请分析 @file:notexist.txt
   ```

3. 查看不存在的文件:
   ```
   > /file show invalid-id-12345
   ```

**预期结果**:
- ✓ 上传时显示清晰的错误提示："文件不存在"
- ✓ 引用时显示："文件 'notexist.txt' 不存在"
- ✓ 查看时显示："文件不存在"
- ✗ 不应该有异常或崩溃

---

### 场景 9: 错误处理 - 不支持的文件类型

**目标**: 验证文件类型验证

**步骤**:

1. 创建一个不支持的文件类型:
   ```bash
   echo "test" > test-data/test.exe
   ```

2. 尝试上传:
   ```
   > /file upload test-data/test.exe
   ```

**预期结果**:
- ✓ 显示错误："不支持的文件类型: .exe"
- ✓ 提示支持的文件类型列表
- ✗ 文件未被上传（使用 /file list 验证）

---

### 场景 10: 错误处理 - 文件过大

**目标**: 验证文件大小限制

**步骤**:

1. 创建一个大文件（> 5 MB）:
   ```bash
   dd if=/dev/zero of=test-data/large.txt bs=1M count=6
   ```

2. 尝试上传:
   ```
   > /file upload test-data/large.txt
   ```

**预期结果**:
- ✓ 显示错误："文件过大: 6.0 MB，最大允许 5 MB"
- ✗ 文件未被上传

---

### 场景 11: 内容截断

**目标**: 验证超长内容截断功能

**步骤**:

1. 创建一个超长文件:
   ```bash
   for i in {1..500}; do echo "这是第 $i 行，包含一些重复的内容" >> test-data/long.txt; done
   ```

2. 上传文件:
   ```
   > /file upload test-data/long.txt
   ```

3. 查看文件详情:
   ```
   > /file show <file-id>
   ```

4. 在对话中引用:
   ```
   > 总结 @file:long.txt 的内容
   ```

**预期结果**:
- ✓ 文件成功上传
- ✓ 详情中显示"是否截断: 是"
- ✓ 显示原始长度和处理后长度
- ✓ 对话中能正常引用（虽然内容被截断）

## 🎯 验收标准

### 功能完整性

- [ ] 可以上传文本、代码、配置文件
- [ ] 可以列出、查看、删除文件
- [ ] **可以在对话中用 `@file:` 引用文件** ⭐
- [ ] **可以同时引用多个文件** ⭐
- [ ] 可以将文件内容提取到记忆
- [ ] 文件与会话正确关联

### 用户体验

- [ ] 所有命令输出清晰友好
- [ ] 错误提示具体且有帮助
- [ ] 文件引用在对话中自然流畅
- [ ] Agent 能正确理解和处理文件内容

### 鲁棒性

- [ ] 文件不存在时有友好提示
- [ ] 不支持的文件类型被正确拒绝
- [ ] 文件过大时有明确限制提示
- [ ] 超长内容正确截断
- [ ] 没有崩溃或未处理异常

### 性能

- [ ] 文件上传响应时间 < 1 秒
- [ ] 文件列表加载 < 500ms
- [ ] 文件内容读取 < 100ms
- [ ] 对话中文件引用解析 < 500ms
